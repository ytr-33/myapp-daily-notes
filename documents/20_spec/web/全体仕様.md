以下は Java API と連携する Web アプリ（Daily Notes）の全体仕様です。

# 全体仕様（Web）

## 1. 目的
- Java 側 API と連携し、ユーザー情報を管理する簡易アプリを提供する。
- CRUD と検索（メール）を最小機能として扱う。

## 2. 想定ユーザー
- 開発者（動作確認、デモ用途）
- 管理者（ユーザーの登録・更新・削除）

## 3. 対象機能
- ユーザー一覧の表示
- ユーザー詳細の表示
- ユーザー作成
- ユーザー更新
- ユーザー削除
- メールアドレス検索
- API ヘルスチェックの表示

## 4. 画面一覧
- 画面一覧は [documents/20_spec/web/画面一覧.md](documents/20_spec/web/画面一覧.md) を参照。

## 5. API 連携仕様
### 5-1. エンドポイント一覧
- `GET /api/users` : ユーザー一覧取得
- `GET /api/users/{id}` : ユーザー詳細取得
- `GET /api/users/search/email?email=...` : メール検索
- `POST /api/users` : ユーザー作成
- `PUT /api/users/{id}` : ユーザー更新
- `DELETE /api/users/{id}` : ユーザー削除
- `GET /api/health` : ヘルスチェック（存在する前提）

### 5-2. 画面とAPIの対応
- ホーム/ダッシュボード
	- ヘルスチェック
	- ユーザー数表示（`GET /api/users`）
- ユーザー一覧
	- 一覧取得（`GET /api/users`）
	- メール検索（`GET /api/users/search/email`）
- ユーザー詳細
	- 詳細取得（`GET /api/users/{id}`）
- ユーザー作成
	- 作成（`POST /api/users`）
- ユーザー編集
	- 詳細取得（`GET /api/users/{id}`）
	- 更新（`PUT /api/users/{id}`）
- ユーザー削除
	- 削除（`DELETE /api/users/{id}`）

## 6. バリデーション/エラー表示
- バリデーションエラーは API のエラー内容を画面に表示する。
- 代表的なステータスと扱い:
	- `400` : 入力エラーとしてフォーム上に表示
	- `404` : 対象なし（詳細画面で「見つかりません」）
	- `409` : メール重複（作成/更新フォームで表示）
	- `500` : システムエラーとして共通エラー表示

## 7. UI 方針
- シンプルな一覧 + 詳細 + 編集の構成
- 操作は最低限の導線にする
